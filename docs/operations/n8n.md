# Self-hosted newsroom automation

This server now hosts a dedicated n8n Community instance. The reader site stays on Vercel, publishing stays in Cloudflare/D1 and content stays in Sanity. There is no n8n Cloud subscription or separate model API key: Codex uses the existing ChatGPT login and its allowance. Authentication expiry, exhausted allowance and the server being down stop processing; this is not unlimited or offline AI.

## Access and installed services

- Private editor: `http://localhost:5678/setup` in this server's T3 preview. This address refers to the server, not the user's phone/laptop. Complete the owner account privately. No owner password was generated by the agent. No public n8n hostname or tunnel is exposed.
- From a trusted computer, an SSH forward (`ssh -L 5678:127.0.0.1:5678 <your-server>`) also reaches the editor. A public hostname requires HTTPS and authentication before changing the loopback binding or secure-cookie setting.
- Compose project `token-on-air-automation`; containers `token-on-air-n8n`, `token-on-air-coordinator`, `token-on-air-codex`. Only n8n publishes a port, on 127.0.0.1. No Docker socket or host home is mounted. All unrelated containers are untouched.
- Pinned n8n 2.44.6; Node 22.23.1 base images pinned by digest; host standalone Codex 0.163.0 copied into the agent image (same CPU architecture required). Private build context contains application bundles/binary only, never auth or publishing secrets.
- Dedicated persistent volumes `token-on-air-automation_n8n_data` and `token-on-air-automation_coordinator_data`. Private authentication/encryption/service files are under `.private/n8n` (ignored, directory 0700/files 0600). Keep the n8n encryption key with database backups: without it encrypted credentials cannot be recovered.

## Start, update, import

Run `npm ci`, then `node scripts/start-n8n.mjs` from this worktree. Requires the existing private Cloudflare service credentials, host Codex login and passwordless Docker sudo. Preparation never overwrites an existing agent auth file/key. Images run with this host user's numeric UID/GID; the start helper initializes only this project's volume roots. n8n uses a writable private cache tmpfs because its stock image assumes UID 1000.

On first installation, after n8n is healthy:

```sh
sudo -n docker exec token-on-air-n8n n8n import:credentials --input=/import/credentials.json
sudo -n docker exec token-on-air-n8n n8n import:workflow --input=/import/workflows.json
```

Remove `.private/n8n/import/credentials.json` after import; it contains a temporary plaintext coordinator credential. Preparation recreates it for an intentional import. Reimporting workflows restores the committed inactive definitions; export/back up intentional editor changes first. Do not run import commands alongside first-start migrations.

Both workflows are imported **unpublished**:

- `toa-smoke`: manual synthetic multilingual generation, followed by a fresh verifier run that must reject unsupported claims. No source queue/CMS writes. Uses two actual Codex calls.
- `toa-queue`: manual or five-minute trigger; one worker job per tick. Currently returns `paused`, without model calls or queue claims. When activated, discovers original evidence, writes three editions, independently checks claims/translations/originality/duplicates, validates exact snapshot excerpts, then signs outside Codex and submits to Cloudflare. Same model in a separate context is a useful check, not a guarantee of factual accuracy.

Execute CLI tests in a separate one-off container so its task broker cannot conflict with the editor:

```sh
sudo -n docker compose --env-file .private/n8n/compose.env -f deploy/n8n/compose.yaml run --rm --no-deps n8n execute --id=toa-smoke
```

The CLI prints execution data; keep full output in private logs, never paste it into public issues. HTTP-only workflows do not use Python/Code nodes. n8n's internal runner reports missing Python and a deprecation; an external runner is needed before adding those nodes.

## Bounds, failures and operations

One model task at a time, 60-second subprocess timeout and 256 KiB output cap; four possible fresh-context tasks per article. Coordinator has one in-flight run, a 230-second processing deadline, explicit lease checks and no blind publish retry. Worker jobs still have five-minute leases and existing attempt/hold rules. Failed, missing-evidence or expired-lease jobs are not self-released. Inspect D1 and CMS after ambiguous publish failure before using the existing admin release/correction endpoints. Some stories will be held rather than guessed. Research URLs must occur in the discovery HTML and use fixed primary source hosts; fetches use DNS pinning, size limits and checked HTTPS redirects.

Run metadata/results retain seven days, at most 1000 rows; n8n executions have the same age/count bounds, successful/manual execution storage disabled. Docker logs rotate at 2×5 MB per service. Application state is durable across container restart, not server/disk loss. Keep private backups off the server using your own encrypted storage; no external storage was provisioned.

Before an update, take a consistent SQLite backup of BOTH volumes and privately copy `.private/n8n/secrets` plus `.private/n8n/auth`. Stop only these three services for a simple cold backup (`docker compose ... stop`), archive these dedicated volumes with a temporary Docker volume mount, then restart. Preserve ownership and permissions. Never run `down -v` against the installed project unless deliberately erasing its data. Restoring backups must use the matching encryption key. A restore drill/off-server backup schedule remains to be configured.

If Codex auth expires, authenticate privately inside this dedicated environment or seed an updated login through private local storage while the agent is stopped; retain the refreshed file. Do not repeatedly overwrite it with an older host copy. Failed auth/quota is recorded as failed, not published. Revoke the dedicated login/private credentials when retiring the service.
